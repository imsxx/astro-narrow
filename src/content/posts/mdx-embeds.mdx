上一篇是纯 Markdown。需要按钮、标签页、视频这类结构化内容时，把文件后缀改成 `.mdx`，然后在 front matter 下面 `import` 对应组件——就像这个文件开头那样。

组件都放在 `src/components/embeds/`，想加新的就往这个目录里放，用起来和普通 Astro 组件一样。

```mdx
import Button from "@/components/embeds/Button.astro"
import LinkCard from "@/components/embeds/LinkCard.astro"
import Tabs from "@/components/embeds/Tabs.astro"
import Tab from "@/components/embeds/Tab.astro"
```

## 按钮

`text` 是按钮文字，`url` 决定跳转地址；不写 `url` 就是一个纯视觉按钮。

<Button url="https://astro.build" target="_blank" icon="external-link" text="Astro 官网" />

<Button url="/posts" variant="outline" text="浏览全部文章" />

<Button variant="secondary" size="lg" text="大号次要按钮" />

<Button variant="#FF5733" text="自定义颜色" />

`variant` 接受内置样式名（`outline`、`secondary` 等），也接受任意颜色值；`size` 可选 `sm`、`md`、`lg`。

## 标签页

需要并排展示多种等价内容时用 `Tabs` + `Tab`。每个面板里可以放任意 Markdown，不只是代码：

<Tabs>
<Tab label="安装">

```bash
pnpm install
```

或者用你习惯的包管理器，仓库里 `packageManager` 锁定的是 pnpm。

</Tab>
<Tab label="配置">

站点信息集中在 `src/config/site.ts`，改标题、描述、导航都在这一处：

```ts
export const siteConfig = siteConfigSchema.parse({
  title: "astro-narrow",
  description: "一个安静的单栏博客主题",
  lang: "zh-hans",
})
```

</Tab>
<Tab label="构建">

```bash
pnpm check   # 类型检查
pnpm build   # 产出 dist/
```

`pnpm check` 会把 `.astro` 和 `.ts` 一起过一遍，比只跑构建更容易提前发现问题。

</Tab>
</Tabs>

## 视频

B 站用视频编号，`av` 和 `BV` 两种写法都认，分 P 用 `page`：

<Bilibili vid="BV1GJ411x7h7" />

腾讯视频用 `vid`：

<Tencent vid="u0025demo0001" />

嵌入的是官方 iframe 播放器，页面里不会额外加载播放器 SDK。示例里的 `vid` 是占位值，换成自己的视频编号即可。

## 什么时候不用组件

纯文字内容仍然建议用 `.md`。MDX 会多一层编译，而且组件写错会直接让构建失败——对纯文本文章来说，这个约束没有收益。

需要在文章里插一个固定结构，并且希望参数写错时立刻报错，才值得换成 `.mdx`。
